## 1. Загальний опис стеку

### 1.1. Концепція

Tauri v2 — це фреймворк для створення настільних (і мобільних) додатків, де **бекенд написаний на Rust**, а **інтерфейс користувача** рендериться через **системний WebView** (на Windows — Microsoft Edge WebView2). На відміну від Electron, Tauri не постачає власний браузерний рушій — він використовує вже встановлений WebView2, що різко зменшує розмір бінарного файлу.

### 1.2. Ключові переваги для AudioCaptor

| Перевага | Деталі |
|----------|--------|
| **Мінімальний розмір exe** | Базовий бінарний файл ~600 КБ — 3 МБ (залежно від залежностей). З усіма аудіо-бібліотеками очікується 5–10 МБ. |
| **Нативна продуктивність** | Rust backend для аудіо-обробки: WASAPI, мікшування, запис WAV — все виконується в нативному коді без GC. |
| **Гнучкий UI** | HTML/CSS/JS дозволяє створити повністю доступний інтерфейс з WAI-ARIA, клавіатурною навігацією, мнемоніками. |
| **Плагінна система** | Tauri v2 має офіційні плагіни: global-shortcut, single-instance, logging, notification та інші. |
| **Безпека** | IPC через команди з явними дозволами (capabilities), ізоляція фронтенду від системних API. |

### 1.3. Версії основних компонентів

## 2. Rust Backend — бібліотеки та компоненти

### 2.1. Tauri Core (`tauri` crate)

- **Версія:** 2.10.3
- **Що робить:** Ядро фреймворку. Управляє вікнами, IPC (команди + події), станом додатку, плагінами, конфігурацією, збіркою.
- **Чому обрано:** Єдиний зрілий Rust-based фреймворк для десктоп-додатків з web-frontend. Активно розвивається (оновлення кожні 2–4 тижні).
- **Альтернативи розглянуті:**
  - *Electron* — великий розмір (150+ МБ), JavaScript runtime, не відповідає вимозі портативності.
  - *Wails (Go)* — менша екосистема, Go замість Rust, менш гнучка аудіо-обробка.
  - *Нативний Win32/WinUI* — складна розробка UI, менше можливостей i18n/a11y.

### 2.2. Аудіо-захоплення: `wasapi` crate

- **Версія:** 0.17.0 (остання стабільна)
- **Репозиторій:** [github.com/HEnquist/wasapi-rs](https://github.com/HEnquist/wasapi-rs)
- **Що робить:** Прямі, безпечні Rust-обгортки навколо Windows Audio Session API (WASAPI). Підтримує:
  - Захоплення з мікрофона (input devices)
  - **Loopback-запис** (системний звук) через `AUDCLNT_STREAMFLAGS_LOOPBACK`
  - Перелік аудіопристроїв, моніторинг підключення/відключення
  - Ексклюзивний та спільний режими
  - Налаштування формату (sample rate, bit depth, кількість каналів)
- **Чому обрано:**
  - Пряме управління WASAPI без додаткових абстракцій — критично для loopback-запису.
  - Вбудована підтримка loopback (є приклад `loopback.rs` у репозиторії).
  - Використовується в продакшен-проєктах (наприклад, CamillaDSP).
  - Мінімальні залежності, Windows-only за дизайном (що відповідає вимозі OC-1).
- **Альтернативи розглянуті:**
  - *cpal* — крос-платформна бібліотека, має WASAPI backend. Loopback-підтримка існує (output device як input), але нестабільна — є відкриті баги (#516, #476). Для Windows-only проєкту `wasapi` надає більше контролю.
  - *windows-rs* (прямі COM bindings) — занадто низькорівневий, потребує багато unsafe коду.

### 2.3. Запис WAV: `hound` crate

- **Версія:** 3.5.1
- **Репозиторій:** [github.com/ruuda/hound](https://github.com/ruuda/hound)
- **Що робить:** Читання та запис WAV-файлів. Підтримує:
  - WavWriter з налаштуванням WavSpec (sample rate, bit depth, кількість каналів)
  - Запис семплів через `write_sample()`
  - Фіналізація файлу при drop або явний виклик `finalize()`
  - Формати: PCM 8/16/24/32-bit, IEEE Float 32-bit
- **Чому обрано:**
  - Стандарт де-факто для WAV у Rust-екосистемі.
  - Простий API, мінімальні залежності, добре протестовано.
  - Підтримує всі необхідні sample rates: 8000, 16000, 44100, 48000 Гц.
- **Альтернативи розглянуті:**
  - *wavers* — менш зріла бібліотека, менше завантажень.
  - *Ручна імплементація WAV* — непотрібна складність при наявності hound.

### 2.4. Аудіо-обробка та мікшування: `dasp` crate

- **Версія:** 0.11.0
- **Репозиторій:** [github.com/RustAudio/dasp](https://github.com/RustAudio/dasp)
- **Що робить:** Фундаментальні типи та функції для DSP (Digital Signal Processing):
  - Трейт `Sample` — абстракція над різними форматами семплів (i16, f32, тощо)
  - Трейт `Frame` — робота з каналами (моно, стерео)
  - Трейт `Signal` — потоковий ітератор фреймів з операціями: add_amp (мікшування), scale_amp (гучність), clip_amp (кліпінг)
  - Конвертація між форматами, ресемплінг
  - **Без динамічних алокацій, без залежностей**
- **Чому обрано:**
  - Ідеально для реального часу: zero-alloc, передбачувана продуктивність.
  - Модульна структура: можна підключити тільки потрібні підкрейти (dasp_sample, dasp_frame, dasp_signal).
  - Підтримка операцій, необхідних для FR2: мікшування (add_amp), контроль гучності (scale_amp), кліпінг (clip_amp), моно→стерео конвертація (Frame).
- **Альтернативи розглянуті:**
  - *Ручна математика* — працездатно для простих операцій, але dasp надає типобезпеку та оптимізовані реалізації.
  - *fon* — менш зріла бібліотека, менша спільнота.

### 2.5. Ресемплінг: `rubato` crate

- **Версія:** 0.16.2
- **Репозиторій:** [github.com/HEnquist/rubato](https://github.com/HEnquist/rubato)
- **Що робить:** Гнучка конвертація sample rate:
  - Синхронний FFT-based ресемплер (швидкий)
  - Асинхронний sinc ресемплер (висока якість)
  - SIMD оптимізація (x86_64, aarch64)
  - Real-time safe: без алокацій під час обробки
- **Чому обрано:**
  - Необхідний коли мікрофон та loopback мають різні sample rates.
  - Від того ж автора, що й wasapi-rs (HEnquist) — гарантована сумісність.
  - Підтримка всіх необхідних sample rates з FR5.
- **Альтернативи розглянуті:**
  - *dasp resampling* — базовий ресемплінг, але менш оптимізований.
  - *libsamplerate bindings* — C-залежність, не pure Rust.

### 2.6. Звукові сповіщення: `rodio` crate

- **Версія:** 0.20.1 (стабільна) / 0.22.2 (остання)
- **Репозиторій:** [github.com/RustAudio/rodio](https://github.com/RustAudio/rodio)
- **Що робить:** Відтворення аудіо:
  - Підтримка WAV, OGG, FLAC, MP3
  - Автоматичне мікшування кількох джерел
  - Фонова нитка для відтворення
  - Контроль гучності, пауза
- **Чому обрано:**
  - Для FR9 (звукові сповіщення: старт/пауза/стоп запису).
  - Використовує cpal як backend — працює з WASAPI.
  - Простий API: `Sink::try_new() → sink.append(source)`.
- **Програвання з пам'яті (без диска):**
  - `rodio::Decoder::new()` приймає будь-який тип, що реалізує `Read + Seek`, включаючи `std::io::Cursor<&[u8]>`.
  - Звукові файли вбудовуються у бінарний файл на етапі компіляції через макрос `include_bytes!()`.
  - Це означає нульовий час доступу до диска, неможливість "загубити" звукові файли, та повну портативність.
  - **Рекомендація:** зберігати вбудовані звуки у форматі OGG (підтримується через Symphonia backend) для меншого розміру (~10–30 КБ проти ~50–100 КБ WAV).
  - Приклад:
    ```rust
    use std::io::Cursor;
    use rodio::{Decoder, OutputStream, Sink};

    static SOUND_START: &[u8] = include_bytes!("../sounds/start.ogg");

    fn play_notification(data: &'static [u8]) {
        let (_stream, handle) = OutputStream::try_default().unwrap();
        let source = Decoder::new(Cursor::new(data)).unwrap();
        let sink = Sink::try_new(&handle).unwrap();
        sink.append(source);
        sink.sleep_until_end();
    }
    ```
- **Альтернативи розглянуті:**
  - *Windows PlaySound API* — обмежений, блокуючий.
  - *Відтворення через фронтенд (Web Audio API)* — можливо, але потребує взаємодії з IPC та має обмеження autoplay.
  - *kira* — потужніший, але надлишковий для простих сповіщень.

- **Що робить:** Серіалізація/десеріалізація Rust-структур у JSON та навпаки.
- **Чому обрано:**

  - Стандарт де-факто в Rust-екосистемі.

### 2.8. Логування: `tauri-plugin-log`

- **Версія:** відповідно до Tauri plugin workspace v2
- **Документація:** [v2.tauri.app/plugin/logging/](https://v2.tauri.app/plugin/logging/)
- **Що робить:**

  - Підтримка LogDir та Folder targets
  - Ротація логів за розміром файлу
  - Інтеграція з Rust crate `log`
  - Бридж логів між Rust та JavaScript
- **Чому обрано:**

  - Підтримка запису логів у довільну папку (відносно exe для портативності).
- **Альтернативи розглянуті:**

### 2.9. Глобальні гарячі клавіші: `tauri-plugin-global-shortcut`

- **Версія:** 2.x (відповідно до plugin workspace)
- **Документація:** [v2.tauri.app/plugin/global-shortcut/](https://v2.tauri.app/plugin/global-shortcut/)
- **Що робить:**
  - Реєстрація глобальних гарячих клавіш (працюють навіть коли додаток не у фокусі)
  - Підтримка модифікаторів: Ctrl, Alt, Shift, Super
  - **Два стани подій: `Pressed` та `Released`** — критично для детекції короткого/довгого натискання
  - API доступний і з Rust, і з JavaScript
- **Як реалізувати коротке/довге натискання (FR3):**
  ```
  Pressed → запам'ятати timestamp
  Released → порівняти з timestamp:
    < 500мс → коротке натискання (start/stop)
    ≥ 500мс → довге натискання (pause/resume)
  ```
- **Підтримка клавіші Pause/Break:** Плагін базується на crate `global-hotkey` від Tauri, який використовує стандартні віртуальні коди клавіш Windows. Клавіша Pause/Break має VK_PAUSE — підтримується.
- **Чому обрано:** Офіційний плагін, нативна інтеграція з Tauri, підтримка Pressed/Released.
- **Альтернативи розглянуті:**
  - *rdev* — низькорівнева бібліотека, KeyPress/KeyRelease з timestamp. Можна використати як fallback, якщо global-shortcut не підтримить Pause/Break.
  - *InputBot* — менш зріла, менше документації.

### 2.10. Єдиний екземпляр: `tauri-plugin-single-instance`

- **Версія:** 2.x (plugin workspace)
- **Документація:** [v2.tauri.app/plugin/single-instance/](https://v2.tauri.app/plugin/single-instance/)
- **Що робить:** Гарантує, що працює лише один екземпляр додатку. При спробі запустити другий — фокус переходить на існуючий.
- **Чому обрано:** Запобігає конфліктам доступу до аудіопристроїв та файлів налаштувань.

### 2.11. Обробка помилок: `thiserror` + `anyhow`

- **Версії:** thiserror 2.x, anyhow 1.x
- **Що роблять:**
  - `thiserror` — деривація `Error` для типізованих помилок, серіалізація для Tauri IPC.
  - `anyhow` — зручна обробка помилок у неекспонованому коді.
- **Чому обрано:** Стандартна практика в Rust. Tauri команди потребують `Result<T, E>` де E: Serialize.

### 2.12. Керування конфігурацією: `directories` crate (НЕ використовується)

> **Важливо:** Для портативного режиму (OC-2, OC-3) ми **НЕ** використовуємо стандартні директорії ОС. Замість цього всі шляхи обчислюються відносно розташування exe-файлу через `std::env::current_exe()`.

## 3. Web Frontend — фреймворк та бібліотеки

### 3.1. Svelte 5

- **Версія:** 5.x (остання стабільна, ~5.15+)
- **Сайт:** [svelte.dev](https://svelte.dev)
- **Що робить:** Компільований UI-фреймворк. Компілює компоненти у ефективний JavaScript при збірці (а не в runtime).
- **Чому обрано для AudioCaptor:**

  1. **Вбудована перевірка доступності (a11y) на рівні компілятора:**
     - Svelte попереджає при компіляції про проблеми доступності: відсутні alt-атрибути, некоректні ARIA-ролі, відсутні keyboard handlers для mouse events, проблеми з accesskey та інше.
     - Це **унікальна перевага** серед фронтенд-фреймворків — критично для OC-6 (HIGHEST PRIORITY a11y).

  2. **Мінімальний розмір бандлу:**
     - Runtime Svelte 5: ~2–3 КБ (min+gzip).
     - Реальні додатки на Svelte 5 мають на ~50% менший бандл порівняно зі Svelte 4.
     - Для Tauri це означає менший WebView payload, швидший запуск.

  3. **Реактивність через signals (runes):**
     - Svelte 5 використовує signals runtime ($state, $derived, $effect) — ефективне оновлення DOM.
     - Ідеально для реал-тайм UI (рівні гучності, стан запису).

  4. **Шаблони Tauri:**
     - `create-tauri-app` має офіційний шаблон для Svelte.
     - Команда: `npm create tauri-app@latest -- --template svelte-ts`

- **Бенчмарки (2026):**
  - Initial bundle: ~8.2 КБ (vs React 18: ~47 КБ — на 83% менше JS)
  - Time-to-interactive: ~156мс (vs React 18: ~340мс — на 78% швидше)
  - Пам'ять: 2.1 МБ baseline / 3.4 МБ peak (vs React 18: 4.8 / 8.2 МБ — на 56–59% менше)
  - У js-framework-benchmark Svelte 5 стабільно в Top 3; SolidJS трохи швидший у raw DOM, але різниця непомітна для 95% додатків
  - ~85K GitHub зірок, ~2M+ npm завантажень/тиждень (у 2–4 рази більше ніж SolidJS)

- **Альтернативи розглянуті:**
  - *SolidJS 1.9* (v2.0 у beta з 2026-03-03) — відмінна runtime-продуктивність (Top 1–2 у бенчмарках), але:
    - **Немає compile-time a11y перевірок** — залежить від runtime бібліотек
    - Kobalte (1700+ зірок) — production-ready a11y UI toolkit, але Solid Aria — "not ready for production"
    - Менша спільнота (~35K зірок, ~1M npm/тиждень), менше UI-бібліотек
    - v2.0 у beta — перехідний період, екосистема адаптується
  - *React* — великий runtime (~40 КБ), надлишковий для простого UI
  - *Vanilla JS/TS* — нульовий overhead фреймворку, але:
    - VU-метри, вибір пристроїв, панель налаштувань потребують реактивності — по суті, довелося б написати міні-фреймворк
    - Немає compile-time a11y перевірок, повна ручна робота з ARIA
    - Не рекомендовано для додатку з реактивним UI
  - *Vue* — хороший варіант, але Svelte має перевагу в a11y та розмірі бандлу

- **Репозиторій:** [github.com/opral/paraglide-js](https://github.com/opral/paraglide-js)
- **Сайт:** [inlang.com/m/gerre34r/library-inlang-paraglideJs](https://inlang.com/m/gerre34r/library-inlang-paraglideJs)
- **Що робить:** Compiler-based i18n — генерує типізовані функції повідомлень при збірці:
  - Кожне повідомлення стає типізованою функцією з параметрами (повна типобезпека)
  - Tree-shakeable — невикористані повідомлення не потрапляють у бандл
  - Нульовий runtime overhead (compiled output, не runtime-бібліотека)
  - Vite plugin (`@inlang/paraglide-js/vite`) — працює без залежності від SvelteKit
  - Нативна підтримка Svelte 5 runes (`$props()`, `$effect`)
  - Офіційна інтеграція в Svelte CLI (рекомендується у документації Svelte)
- **Як реалізувати FR7:**
  ```
  messages/
    en.json    — англійська
    uk.json    — українська
  ```
  - Paraglide автоматично генерує типізовані функції з JSON-файлів повідомлень.
  - Використання у шаблонах: `import * as m from '$lib/paraglide/messages'; m.recording_started()`
  - Автодетекція мови системи: через `navigator.language` або Rust API.
  - **Жодної підтримки російської мови** — файл `ru.json` не створюється. Якщо системна мова — ru, fallback на uk.
  - Зміна мови в налаштуваннях → оновлення параметра мови Paraglide.
- **Чому обрано замість svelte-i18n:**

  | Критерій | Paraglide JS 2.0 | svelte-i18n 4.0.1 |
  |----------|-------------------|-------------------|
  | Svelte 5 runes | Нативна підтримка | Тільки backward compat (stores) |
  | Типобезпека | Повна — кожне повідомлення є типізованою функцією | Немає |
  | Розмір бандлу | До 70% менший (compiled) | Runtime-based (середній) |
  | Підтримка | Активна, офіційна інтеграція Svelte | Повільна, відкритий Issue #248 щодо Svelte 5 |
  | Peer dependency | Немає проблем | Потребує `--force` для Svelte 5 |

- **Локалізація Rust-сторони (стратегія):**
  - Rust бекенд **не формує** рядки для користувача — повертає структуровані коди помилок (`"error.device_lost"`, `"state.recording"` тощо).
  - Фронтенд маппить коди → локалізовані рядки через Paraglide.
  - Це повністю усуває дублювання перекладів між Rust та фронтендом.
  - Якщо у майбутньому знадобиться локалізація Rust-сторони (наприклад, system tray) — використати крейт `rust-i18n` з тими ж JSON-файлами.
- **Альтернативи розглянуті:**
  - *svelte-i18n 4.0.1* — працює зі Svelte 5 через backward compat, але використовує застарілі stores, немає типобезпеки, повільна підтримка.
  - *svelte-i18next* — не підтримується (2+ роки без оновлень), не рекомендовано.
  - *typesafe-i18n* — типобезпечна, працює зі Svelte 5, але потребує генератора та має повільніший цикл оновлень.
  - *tauri-plugin-i18n* — community плагін з Rust-стороною. Варіант для серверних рядків, але для фронтенд-only перекладів Paraglide простіша та ефективніша.

### 3.3. CSS / Стилізація

- **Підхід:** Вбудовані стилі Svelte (`<style>` у компонентах) + CSS Custom Properties для темізації.
- **Чому:** Мінімальний overhead, scoped стилі, не потребує додаткових залежностей.
- **a11y вимоги до стилів:**
  - Високий контраст (WCAG AA мінімум)
  - `focus-visible` для клавіатурної навігації
  - Достатні розміри елементів (min 44x44px для touch-like targets)
  - `prefers-reduced-motion` підтримка
  - `prefers-color-scheme` для підтримки системної теми (опціонально)

- **Версія:** 6.x (остання стабільна)

- **Чому:** Стандарт для Tauri + Svelte. Швидкий HMR під час розробки, оптимізовані бандли для продакшну.

- **Чому:** Типобезпека для IPC-викликів, авто-завершення для Tauri API, покращена підтримуваність коду.

### 4.2. IPC дизайн (Tauri Commands + Events)

#### 4.2.1. Tauri Commands (Frontend → Rust)

Команди викликаються з фронтенду через `invoke()` і повертають результат:

```typescript
// Типізовані виклики з фронтенду
import { invoke } from '@tauri-apps/api/core';

// Аудіо-пристрої
invoke<AudioDevice[]>('list_audio_devices');
invoke('select_microphone', { deviceId: 'mic-1' });
invoke('select_loopback', { deviceId: 'loop-1' });
invoke('refresh_devices');

// Запис
invoke('start_recording', { profileId: 'default' });
invoke('pause_recording');
invoke('resume_recording');
invoke('stop_recording');

// Налаштування
invoke<AppSettings>('get_settings');
invoke('save_settings', { settings: {...} });
invoke<RecordingProfile[]>('list_profiles');
invoke('save_profile', { profile: {...} });
invoke('delete_profile', { profileId: '...' });

// Гарячі клавіші
invoke('update_hotkey', { key: 'Pause', modifiers: [] });
invoke('capture_hotkey_start');
invoke('capture_hotkey_stop');

// Гучність
invoke('set_microphone_volume', { volume: 1.0 });
invoke('set_loopback_volume', { volume: 1.0 });
```

#### 4.2.2. Tauri Events (Rust → Frontend)

Події для стрімінгу даних та оповіщень:

```typescript
import { listen } from '@tauri-apps/api/event';

// Стан запису змінився
listen<RecordingState>('recording-state-changed', (event) => {
  // { state: 'recording' | 'paused' | 'idle', duration_ms: number }
});

// Рівні аудіо (для VU-метрів)
listen<AudioLevels>('audio-levels', (event) => {
  // { mic_level: f32, loopback_level: f32, mix_level: f32 }
});

// Пристрої змінились
listen('audio-devices-changed', () => { /* оновити список */ });

// Гаряча клавіша захоплена
listen<HotkeyCapture>('hotkey-captured', (event) => {
  // { key: 'F9', modifiers: ['Ctrl'] }
});

// Помилки
listen<AppError>('recording-error', (event) => {
  // { code: 'DEVICE_LOST', message: '...' }
});
```

### 4.4. FSM (Finite State Machine) стану запису

```
        start (short press)
 IDLE ─────────────────────► RECORDING
  ▲                            │    │
  │    stop (short press)      │    │ pause (long press)
  │◄───────────────────────────┘    │
  │                                 ▼
  │    stop (short press)        PAUSED
  │◄────────────────────────────   │
  │                                │ resume (long press)
  └────────────────────────────────┘
           (через RECORDING)
```

**Логіка гарячої клавіші:**
- `Pressed` → зберегти `press_timestamp`
- `Released` → обчислити `duration = now - press_timestamp`
  - Якщо стан == IDLE:
    - Будь-яка тривалість → START (перехід до RECORDING)
  - Якщо стан == RECORDING:
    - duration < 500мс → STOP (перехід до IDLE)
    - duration ≥ 500мс → PAUSE (перехід до PAUSED)
  - Якщо стан == PAUSED:
    - duration < 500мс → STOP (перехід до IDLE)
    - duration ≥ 500мс → RESUME (перехід до RECORDING)

1. **WebView2 Issue #2330 (Microsoft):** WebView2 control повідомляється як "повністю недоступний" з NVDA, JAWS, та частково з Narrator. Tab-навігація не працює, контент не озвучується. | Захід | Деталі |
|-------|--------|
| **ОБОВ'ЯЗКОВО: `decorations: true`** | Використовувати нативну рамку вікна Windows. НЕ використовувати frameless mode. Це обходить Issue #12901. |
| **WAI-ARIA розмітка** | Кожен елемент UI має мати `role`, `aria-label`, `aria-describedby`, `aria-live` де потрібно. |
| **aria-live регіони** | Для анонсів стану запису: `<div role="status" aria-live="assertive">` — "Запис розпочато", "Запис призупинено", "Запис завершено". |
| **Клавіатурна навігація** | Tab для переміщення між елементами, Enter для активації, Escape для закриття діалогів. Власні обробники `keydown`. |
| **Мнемоніки** | `accesskey` атрибути для швидкого доступу (з обережністю — Svelte попереджає про конфлікти). Альтернатива: підкреслені літери в мітках з кастомною обробкою Alt+літера. |
| **Тестування** | Регулярне тестування з NVDA (безкоштовний), Narrator (вбудований), JAWS (платний). |
| **NVDA App Module** | При потребі — створити NVDA app module (Python, ~3 рядки) що відключає Browse Mode для AudioCaptor. |

### 6.1. Передумови збірки

```bash

pnpm install

# Розробка з HMR
pnpm tauri dev

# Продакшн збірка
pnpm tauri build

```

### 6.3. Оптимізація розміру бінарного файлу

У `src-tauri/Cargo.toml`:
```toml
[profile.release]
panic = "abort"        # Вимкнути panic unwinding
codegen-units = 1      # Краща оптимізація
lto = true             # Link-Time Optimization
opt-level = "s"        # Оптимізація за розміром
strip = true           # Видалити debug символи
```

У `src-tauri/tauri.conf.json`:
```json
{
  "build": {
    "removeUnusedCommands": true
  }
}
```

**Додатково для статичної лінковки CRT:**
```bash
# .cargo/config.toml
[target.x86_64-pc-windows-msvc]
rustflags = ["-C", "target-feature=+crt-static"]
```

### 6.4. Продукування портативного .exe

**Крок 1:** Збірка
```bash
pnpm tauri build --bundles none
```
Використання `--bundles none` пропускає створення інсталяторів і залишає лише сирий .exe у `target/release/`.

**Крок 2:** Перевірка залежностей
```bash
# Перевірити що немає DLL-залежностей (крім системних)
dumpbin /dependents target/release/AudioCaptor.exe
```
Очікувані залежності: лише системні DLL (kernel32.dll, user32.dll, ole32.dll, тощо). Якщо є vcruntime140.dll — потрібна статична лінковка CRT.

**Крок 3:** Розповсюдження
- Один файл: `AudioCaptor.exe` (~5–10 МБ)
- Zip-архів для Scoop: `AudioCaptor-v1.0.0-portable.zip` (містить лише .exe)
- При першому запуску exe створює поруч із собою: `settings.json`, `logs/`, `recordings/`

## 7. Ризики, обмеження та пом'якшення

### 7.1. КРИТИЧНИЙ: Доступність WebView2 зі зчитувачами екрана

| Аспект | Деталі |
|--------|--------|
| **Рівень ризику** | 🔴 КРИТИЧНИЙ |
| **Опис** | WebView2 має задокументовані проблеми з NVDA та JAWS (GitHub Issue MicrosoftEdge/WebView2Feedback#2330). Tab-навігація може не працювати, контент може не озвучуватись. |
| **Статус** | Microsoft відстежує проблему, але публічний фікс відсутній станом на 2025. |
| **Пом'якшення** | |

1. **ОБОВ'ЯЗКОВО: Використовувати `decorations: true`** (нативна рамка вікна). Tauri Issue #12901 підтверджує, що frameless вікна повністю ламають доступність. З нативною рамкою ситуація значно краща.

2. **NVDA: Відключення Browse Mode.** Основна проблема NVDA з WebView2 — автоматична активація Browse Mode, який конфліктує з інтерактивними елементами. Рішення:
   - Створити NVDA App Module (appModules/AudioCaptor.py):
     ```python
     import appModuleHandler
     class AppModule(appModuleHandler.AppModule):
         disableBrowseModeByDefault = True
     ```
   - Розповсюджувати як окремий NVDA addon або інструкцію для користувачів.

3. **Правильна WAI-ARIA розмітка:**
   - Всі інтерактивні елементи мають правильні `role`, `aria-label`
   - Використовувати нативні HTML-елементи де можливо (`<button>`, `<select>`, `<input>`) — вони мають вбудовану доступність
   - `aria-live="assertive"` для критичних анонсів (стан запису)
   - `aria-live="polite"` для інформаційних оновлень (рівні гучності)

4. **Тестування з кожним зчитувачем:**
   - NVDA (безкоштовний) — основний зчитувач для тестування
   - Narrator (вбудований в Windows) — вторинний
   - JAWS (платний) — тестування перед релізом

5. **Fallback-стратегія:** Якщо WebView2 a11y виявиться неприйнятною → розглянути міграцію на нативний Win32 UI. Це радикальний крок, але можливий завдяки тому, що backend на Rust залишається незмінним.

### 7.2. ВИСОКИЙ: WebView2 Runtime відсутній

| Аспект | Деталі |
|--------|--------|
| **Рівень ризику** | 🟡 СЕРЕДНІЙ |
| **Опис** | На деяких Windows 10 машинах (корпоративні, обмежені) WebView2 може бути не встановлений. |
| **Статус** | Microsoft розповсюджує WebView2 через Windows Update з 2022–2023. Більшість пристроїв мають його. |
| **Пом'якшення** | |

1. При запуску — перевірка наявності WebView2.
2. При відсутності — показати нативний Windows MessageBox (без WebView) з інструкцією.
3. Опціонально: поставляти WebView2 Bootstrapper (~1.8 МБ) поруч з exe.
4. Для Scoop: додати перевірку WebView2 у pre_install скрипт manifest.

### 7.3. СЕРЕДНІЙ: Розмір exe

| Аспект | Деталі |
|--------|--------|
| **Рівень ризику** | 🟢 НИЗЬКИЙ |
| **Опис** | З аудіо-бібліотеками (wasapi, hound, dasp, rubato, rodio) та Tauri runtime розмір exe може бути 5–15 МБ. |
| **Пом'якшення** | Оптимізація Cargo profile (LTO, strip, opt-level="s"). Мінімізація фронтенд-бандлу (Svelte = ~3 КБ runtime). Звукові файли сповіщень — малий розмір (OGG, ~10–30 КБ кожен). |
| **Прийнятність** | 5–15 МБ — відмінний результат для десктоп-додатку. |

### 7.4. СЕРЕДНІЙ: Глобальна гаряча клавіша Pause/Break

| Аспект | Деталі |
|--------|--------|
| **Рівень ризику** | 🟡 СЕРЕДНІЙ |
| **Опис** | Клавіша Pause/Break може конфліктувати з іншими програмами або не бути присутньою на компактних клавіатурах. |
| **Пом'якшення** | Можливість налаштування гарячої клавіші (FR6). UI для захоплення нової клавіші. Відображення зрозумілого повідомлення при конфлікті. |

### 7.5. НИЗЬКИЙ: Latency при мікшуванні

| Аспект | Деталі |
|--------|--------|
| **Рівень ризику** | 🟢 НИЗЬКИЙ |
| **Опис** | Якщо мікрофон та loopback мають різні sample rates, ресемплінг додає затримку. |
| **Пом'якшення** | rubato підтримує обробку чанками, оптимізовано для реального часу. Типова затримка ресемплінгу: <5мс. Загальна затримка (WASAPI + resample + mix + write): <20мс. |

### 7.6. НИЗЬКИЙ: Оновлення Tauri ламає доступність

| Аспект | Деталі |
|--------|--------|
| **Рівень ризику** | 🟡 СЕРЕДНІЙ |
| **Опис** | Issue #12901 з'явився між tauri 2.2.5 та 2.3.1 — оновлення зламало a11y. Може повторитися. |
| **Пом'якшення** | Зафіксувати версію Tauri до перевіреної. Тестування доступності при кожному оновленні. Lockfile для cargo та npm. Не оновлювати Tauri без тестування з NVDA. |

### 7.7. ІНФОРМАЦІЙНИЙ: Альтернативи Tauri для a11y

Якщо WebView2 a11y виявиться неприйнятною, можливі альтернативи:

| Альтернатива | Переваги | Недоліки |
|-------------|----------|----------|
| **Нативний Win32 UI (windows-rs)** | Повна a11y через UIA | Складна розробка UI, без i18n фреймворків |
| **WinUI 3 / XAML** | Сучасний UI, вбудована a11y | C++/C# прив'язка, складна інтеграція з Rust |
| **AccessKit + egui/iced** | Rust-native, AccessKit для a11y | Менш зрілі a11y реалізації, обмежені стилі |
| **Electron** | Перевірена a11y Chromium | Великий розмір (150+ МБ), не портативний |
