# Швидке відновлення вікна AudioCaptor

> **Тип задачі:** ✨ Фіча
> **Стек:** Rust, Tauri v2, Windows
> **Дата:** 2026-04-20

## TL;DR
> Зараз відновити вікно можна лише через трей (лівий клік або меню). Рекомендоване рішення: **виправити single-instance плагін** — при повторному запуску exe показувати вікно. Це дає природний Windows-паттерн: клікнув іконку в Start Menu / Taskbar → побачив вікно.

## Аналіз проблеми

Поточні способи показати вікно:
1. **Лівий клік на трей-іконці** — вимагає прицілитись мишкою в трей
2. **Меню трея → Show/Hide** — два кліки
3. **Повторний запуск exe** — single-instance плагін робить лише `set_focus()` БЕЗ `show()`, тому приховане вікно не з'являється ← **це баг**

Вікно ховається через `hide()` (Escape / мінімізація в трей), що прибирає його з Alt+Tab і Taskbar.

## Розглянуті рішення

### Варіант A: Виправити single-instance (show + focus)

**Суть:** Змінити обробник single-instance з `set_focus()` на `show()` + `set_focus()`. Після цього повторний запуск `AudioCaptor.exe` (через Start Menu, пін на Taskbar, ярлик) показує вікно.

**Переваги:**
- Мінімальна зміна (1 рядок)
- Природний Windows-паттерн: клікнув на програму = побачив вікно
- Працює з Scoop shortcut (Start Menu), пінкою на Taskbar, командним рядком
- Не вимагає нових гарячих клавіш
- Discoverable — інтуїтивно зрозумілий будь-кому

**Недоліки:**
- Вимагає "дійти до" Start Menu / Taskbar (не миттєве)

**Рівень впевненості:** ✅ підтверджено (API show()+set_focus() вже використовується в tray.rs)

---

### Варіант B: Double-press існуючого hotkey → toggle window

**Суть:** Якщо протягом 300ms після Release приходить ще один Press+Release — трактувати як double-press і toggle вікно.

**Переваги:**
- Миттєве, працює з будь-якого вікна
- Не додає нову гарячу клавішу (мінімалізм)
- Логічне розширення FSM

**Недоліки:**
- Ускладнює hotkey FSM (додається стан очікування double-press)
- Додає затримку 300ms до ВСІХ коротких натисків (idle → start тепер чекає "а раптом буде другий?")
- Менш discoverable — користувач не здогадається без документації
- Конфлікт: що якщо запис активний і подвійний клік? Toggle вікно чи pause+pause?

**Рівень впевненості:** ⚠️ працює технічно, але погіршує UX записування

---

### Варіант C: Зробити вікно мінімізованим замість прихованого

**Суть:** Замінити `hide()` на `minimize()`. Вікно залишається в Taskbar і Alt+Tab.

**Переваги:**
- Стандартна поведінка Windows-програм
- Alt+Tab, Win+Tab, клік на Taskbar — все працює

**Недоліки:**
- Суперечить поточній концепції "мінімізація в трей" (трей-іконка стає зайвою)
- Для портативного рекордера трей-іконка зручніша — програма не засмічує Taskbar
- Потрібна переробка всієї show/hide логіки

**Рівень впевненості:** ⚠️ відходить від дизайн-рішення про тray-only

---

### Варіант D: Комбінація A + використання існуючого hotkey при Idle

**Суть:** A (single-instance fix) + коли запис неактивний і вікно приховане, короткий натиск hotkey показує вікно замість запуску запису.

**Переваги:**
- Hotkey стає "увага до AudioCaptor" а не лише "керування записом"
- Природна логіка: натиснув → побачив стан → натиснув ще раз → пішов запис

**Недоліки:**
- **Ламає існуючу поведінку**: зараз short press при Idle = Start. Користувач чекає запис, а бачить вікно.
- Для скрінрідер-користувачів це катастрофа — вони натискають hotkey щоб записати, не бачачи екрану

**Рівень впевненості:** ❓ спірне — залежить від workflow користувача

## Рекомендація

**Обраний варіант:** A — виправити single-instance

**Чому:**
- Нульовий ризик регресії (не змінює жодну існуючу поведінку)
- Мінімальна зміна коду (1 рядок)
- Природний для Windows — користувач очікує що клік на іконку = вікно з'являється
- Вже працює зі Start Menu shortcut (Scoop `shortcuts` щойно додали)
- Win+[число] для taskbar pin — безкоштовний бонус

**Коли обирати альтернативу:**
- Якщо потрібен миттєвий виклик без миші і Start Menu — тоді **B** (double-press), але з обережністю

## Реалізація

```rust
// src-tauri/src/lib.rs — single-instance handler
.plugin(tauri_plugin_single_instance::init(|app, _args, _cwd| {
    if let Some(w) = app.get_webview_window("main") {
        let _ = w.show();       // ← ДОДАТИ: показати приховане вікно
        let _ = w.set_focus();
    }
}))
```

**Кроки впровадження:**
1. Додати `w.show()` перед `w.set_focus()` в single-instance callback
2. Перевірити: запустити exe коли вікно приховане — вікно має з'явитись

## Ризики та міграція
- Що може піти не так: нічого — `show()` на вже видимому вікні — no-op
- Як відкотити: прибрати один рядок
