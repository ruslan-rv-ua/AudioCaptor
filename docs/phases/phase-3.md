# Етап 3 — Профілі запису та розширені режими виводу

## Мета

Система профілів для збереження та перемикання конфігурацій запису, розширені режими виводу з паралельним записом у декілька файлів, динамічне оновлення пристроїв.

---

## Функціональність

### 1. Система профілів (FR4.1–FR4.7)

- CRUD операції: створення, редагування, видалення профілів
- Структура профілю:
  ```rust
  struct RecordingProfile {
      id: String,
      name: String,           // унікальне, валідоване
      description: String,
      output_folder: PathBuf, // за замовчуванням {exe_dir}/Recordings/
      output_mode: OutputMode,// Microphone | Loopback | Mix | MixPlusMicrophone | MixPlusLoopback
      sample_rate: u32,       // 8000 | 16000 | 44100 | 48000
      mic_volume: f32,        // 0.0–4.0
      loopback_volume: f32,   // 0.0–4.0
      mic_filename: String,   // базове ім'я файлу мікрофона
      loopback_filename: String,
      mix_filename: String,
  }
  ```
- Збереження профілів у `settings.json` (масив)
- Автоматичне створення профілю "Default" при першому запуску (якщо профілів немає)
- Заборона видалення останнього профілю — UI не дозволяє, backend перевіряє
- Унікальність імен профілів — валідація при створенні та редагуванні
- Валідація імен файлів на заборонені символи Windows: `< > : " / \ | ? *`
- Перемикання профілів без перезапуску: при зміні профілю оновити параметри audio engine
- IPC-команди: `list_profiles`, `save_profile`, `delete_profile`, `select_profile`
- UI: діалог створення/редагування профілю, список профілів з вибором активного

### 2. Розширені режими виводу (FR5.4, FR5.5, FR5.7, FR5.9)

- Два нових режими:
  - **Мікс + Мікрофон** (`MixPlusMicrophone`) — паралельний запис у два WAV-файли: `{mix_name}_{ts}.wav` + `{mic_name}_{ts}.wav`
  - **Мікс + Loopback** (`MixPlusLoopback`) — паралельний запис у два WAV-файли: `{mix_name}_{ts}.wav` + `{loopback_name}_{ts}.wav`
- Mixer Thread маршрутизує оброблені дані в 1–2 `WavWriter` залежно від режиму
- Кастомні базові імена файлів для кожного типу (мікрофон, loopback, мікс) — зберігаються в профілі
- Автоматичне іменування: `{custom_name}_{YYYY-MM-DD_HH-MM-SS}.wav`
- Архітектура запису через trait `OutputWriter` для майбутнього додавання форматів (FR5.9):
  ```rust
  trait OutputWriter: Send {
      fn write_samples(&mut self, samples: &[f32]) -> Result<()>;
      fn finalize(self) -> Result<()>;
  }
  ```

### 3. Динамічне оновлення пристроїв (FR1.3, FR1.6)

- Моніторинг підключення/відключення аудіопристроїв через WASAPI `IMMNotificationClient`
- При зміні пристроїв:
  - Оновити список у UI (IPC-подія `audio-devices-changed`)
  - Якщо активний пристрій відключено під час запису — зупинити запис, повідомити користувача (`recording-error` з кодом `DEVICE_LOST`)
- Ручне оновлення списку через IPC-команду `refresh_devices`
- Одночасний запис з мікрофона та loopback (FR1.3) — вже реалізовано в Етапі 1, тут забезпечується стабільність при зміні пристроїв

## Технічні вимоги та обмеження

| Вимога | Деталі |
|--------|--------|
| Паралельний запис | Режими Mix+Mic та Mix+Loopback потребують двох одночасних `WavWriter` — перевірити відсутність блокувань |
| Файлова система | Валідація шляху `output_folder` — перевірити існування, дозволи на запис |
| Міграція | Існуючі `settings.json` без профілів → автоматично створити "Default" профіль з поточними параметрами (`mic_volume`, `loopback_volume`, `output_mode`, `sample_rate` переходять з верхнього рівня в профіль) |
| Пам'ять | `IMMNotificationClient` — COM-об'єкт, потребує правильного часу життя (`Arc<Mutex<>>` або інший механізм) |

### Проміжна структура `settings.json` після Етапу 3

Поля `mic_volume`, `loopback_volume`, `output_mode`, `sample_rate` переходять з верхнього рівня в профілі. `selected_mic`, `selected_loopback`, `hotkey`, `sound_enabled` залишаються на верхньому рівні (пристрої не є частиною профілю за PRD FR4.2).

```json
{
  "selected_mic": null,
  "selected_loopback": null,
  "hotkey": "Pause",
  "sound_enabled": true,
  "profiles": [
    {
      "id": "default",
      "name": "Default",
      "description": "",
      "output_folder": "Recordings",
      "output_mode": "Mix",
      "sample_rate": 48000,
      "mic_volume": 1.0,
      "loopback_volume": 0.5,
      "mic_filename": "mic",
      "loopback_filename": "loopback",
      "mix_filename": "mix"
    }
  ],
  "active_profile_id": "default"
}
```

## Definition of Done

- [ ] Можна створити новий профіль з усіма параметрами
- [ ] Можна відредагувати існуючий профіль
- [ ] Можна видалити профіль (крім останнього)
- [ ] Імена профілів унікальні — дублікат не дозволяється
- [ ] Імена файлів валідуються на заборонені символи Windows
- [ ] Перемикання профілю змінює параметри запису без перезапуску
- [ ] При першому запуску автоматично створюється профіль "Default"
- [ ] Режим "Мікс + Мікрофон" створює два WAV-файли: мікс та мікрофон
- [ ] Режим "Мікс + Loopback" створює два WAV-файли: мікс та loopback
- [ ] Кастомні імена файлів з профілю використовуються у назвах WAV
- [ ] При відключенні пристрою під час запису — запис зупиняється з повідомленням
- [ ] При підключенні нового пристрою — список оновлюється автоматично
- [ ] Усі нові UI-елементи (діалоги профілів) доступні через Tab-навігацію
- [ ] Скрін-рідер озвучує діалоги створення/редагування/видалення профілів
