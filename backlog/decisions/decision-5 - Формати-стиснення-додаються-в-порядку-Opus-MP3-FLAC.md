## Context

<!-- SECTION:CONTEXT:BEGIN -->
Записи AudioCaptor зберігаються лише у WAV 16 біт: година запису 48 кГц стерео займає близько 691 МБ. Дослідження doc-1 (квітень 2026) радило спершу FLAC на кодері `flacenc`, потім MP3 через LAME; MP3 відклали через ліцензію LGPL (чернетка DRAFT-1, тепер TASK-29), а кодери Opus на Rust вважали незрілими.

26 листопада 2026 обставини переглянуто:

- У Windows є власний кодер MP3 (MP3 Audio Encoder у Media Foundation, з Windows 8). З ним не потрібні ні LAME, ні LGPL. Пробний запис 48 кГц, стерео, 128 кбіт/с вийшов правильним. У N-версіях Windows кодера немає без Media Feature Pack.
- Еталонний кодер Opus, libopus, має ліцензію BSD-3-Clause з безоплатною патентною ліцензією, тож його можна вбудувати в exe. З'явилися й кодери Opus на чистому Rust (`opus-pure`, `rusty-opus`), але вони зовсім нові.
- Приріст exe виміряно на пробній збірці з налаштуваннями випуску AudioCaptor (opt-level "s", LTO, статичний CRT): FLAC (`flacenc`) ≈ 195 КБ, з кодуванням у кілька потоків ≈ 265 КБ; MP3 через Windows ≈ 5 КБ; MP3 через LAME ≈ 145 КБ; Opus через libopus разом із контейнером Ogg ≈ 250 КБ; Opus на чистому Rust ≈ 350–435 КБ. FLAC, MP3 через Windows і Opus через libopus разом додають ≈ 0,45 МБ до нинішніх 4,7 МБ.

Година мовлення займає: WAV — 691 МБ, FLAC — близько 230–350 МБ, MP3 на 128 кбіт/с — 58 МБ, Opus на 32 кбіт/с — 14 МБ.
<!-- SECTION:CONTEXT:END -->

## Decision

<!-- SECTION:DECISION:BEGIN -->
Формати стиснення додаються по одному на випуск у такому порядку:

1. Opus — у 0.2.0 (TASK-27, TASK-28);
2. MP3 — у 0.3.0, вбудованим кодером Windows, а не LAME (TASK-29);
3. FLAC — у 0.4.0 (TASK-11, TASK-12).

Порядок вибрав власник 26 листопада 2026.
<!-- SECTION:DECISION:END -->

## Consequences

<!-- SECTION:CONSEQUENCES:BEGIN -->
- Спільну частину для всіх форматів (вибір формату в профілі, кодування у фоні, тимчасовий файл, оголошення для скрінрідера, перехід `settings.json` на версію 6) будує задача про Opus; MP3 і FLAC додають лише свій кодер.
- Першим стає формат зі втратами: розкодований запис не звірити з WAV семпл у семпл, тому WAV типово лишається, а видаляти його можна лише за опцією профілю.
- `.opus` відкривають не всі програвачі (стандартний програвач Windows, за відгуками, без розширень його не відкриває), тож README має назвати програвачі, які його відкривають.
- Кодер Opus вибирає дослідницька задача: libopus (код на C, у збірці потрібен CMake) чи кодер на чистому Rust.
- Профіль із форматом, якого старіша версія програми не знає, має читатися без помилки й писати WAV, щоб повернення до попередньої версії не губило профілів.
- Рекомендації doc-1 щодо порядку форматів і кодера MP3 більше не діють.
<!-- SECTION:CONSEQUENCES:END -->

## Alternatives

<!-- SECTION:ALTERNATIVES:BEGIN -->
- FLAC → MP3 → Opus: найобережніший порядок, бо першим іде формат без втрат; його радили дослідження doc-1 і перегляд 26 листопада. Власник вибрав Opus першим.
- MP3 через LAME (`mp3lame-encoder`): LGPL вимагає постачати LAME окремою DLL або давати об'єктні файли для перезбирання, а це суперечить одному exe.
- FFmpeg: дає всі формати одразу, але додає 30–80 МБ до exe.
<!-- SECTION:ALTERNATIVES:END -->
