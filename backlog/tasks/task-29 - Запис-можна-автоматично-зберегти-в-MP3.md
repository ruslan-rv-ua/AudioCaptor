## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
MP3 — найпоширеніший формат для обміну записами: на 128 кбіт/с файл у 12 разів менший за WAV (година — близько 58 МБ), і його відкриває будь-який програвач чи сервіс. Власник поставив MP3 другим форматом стиснення, після Opus (рішення decision-5).

Раніше MP3 чекав рішення про ліцензію: єдиний зрілий кодер, LAME, поширюється за LGPL, а AudioCaptor — один exe під MIT. Тепер кодувати можна вбудованим кодером Windows — MP3 Audio Encoder з Media Foundation, він є з Windows 8. Стороння бібліотека не потрібна, тож питання LGPL зникає. За пробною збіркою 26 листопада 2026 exe більшає приблизно на 5 КБ (LAME додав би ≈ 145 КБ), а пробний запис 48 кГц, стерео, 128 кбіт/с через Sink Writer вийшов правильним.

Що відомо про кодер із документації Microsoft:

- приймає лише 16-бітний цілочисельний PCM, моно або стерео;
- бітрейт — від 32 до 320 кбіт/с на частотах MPEG-1 (32, 44,1 і 48 кГц); на нижчих частотах (MPEG-2) MP3 не буває більшим за 160 кбіт/с, а про підтримку 8 і 16 кГц сторінки документації суперечать одна одній;
- у N-версіях Windows кодера немає, доки не встановлено Media Feature Pack.

Частота профілю діє для всіх форматів (рішення decision-6): на 8 і 16 кГц програма знижує бітрейт варіантів до можливого, а якщо кодер Windows якоїсь частоти не приймає, перетворює її на найближчу, яку приймає.

Спільну частину — вибір формату в профілі, кодування у фоні, тимчасовий файл, перевірку перед видаленням WAV, оголошення для скрінрідера — будує TASK-28 для Opus; тут додається кодер MP3. Після вдалого запису в теці лишається тільки `.mp3` (рішення decision-7).

У списку формату в профілі (рішення decision-6) MP3 має три варіанти: «MP3 — мовлення» (орієнтовно 64 кбіт/с: голос звучить так само, а година займає близько 29 МБ), «MP3 — стандарт» (128 кбіт/с) і «MP3 — висока якість» (орієнтовно 256–320 кбіт/с, для музики). Для мовлення може вистачити моно. Точні значення для мовлення й високої якості власник затверджує на слух.

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Модуль `convert/mp3.rs`: кодер MP3 Audio Encoder з Media Foundation (перетворювач MFT через CoCreateInstance). `mfplat.dll` завантажується лише під час конвертації (LoadLibraryExW із System32), щоб програма запускалася й у Windows N без Media Feature Pack.
2. Варіанти `Mp3Speech`, `Mp3Standard`, `Mp3High` в `OutputFormat`; бітрейт і канали кожного варіанта. На 8 і 16 кГц — найбільший бітрейт, який дає кодер Windows (decision-6). Частота не перетворюється: кодер приймає 8, 16, 44,1 і 48 кГц.
3. Перевірка перед видаленням WAV: розбір усіх кадрів MP3 від початку до кінця (у кожному кадрі та сама версія MPEG, частота, канали й бітрейт; файл закінчується рівно на кінці кадру) і тривалість: не менша за запис + 1152 семпли і не більша за запис + 4032 семпли.
4. Відсутній кодер (Windows N без Media Feature Pack): окрема помилка конвертації, звук попередження і повідомлення, як установити Media Feature Pack; WAV лишається. Прихований перемикач — змінна середовища `AUDIOCAPTOR_NO_MP3_ENCODER=1` — імітує відсутній кодер для перевірок і `just smoke`.
5. Потік конвертації працює у фоновому режимі Windows (нижчий пріоритет процесора й диска), щоб новий запис мав перевагу.
6. Інтерфейс: три пункти списку «Формат» з бітрейтом у назві, тексти en/uk, тип `OutputFormat` у TypeScript.
7. Тести Rust: налаштування варіантів, кодування й перевірка на 8, 16, 44,1 і 48 кГц, пошкоджені файли, відсутній кодер. Тести, яким потрібен кодер Windows, пропускаються там, де його немає (CI без Media Foundation).
8. Пробні файли для прослуховування й вибір бітрейтів власником (AC #2).
9. README.md, README_UK.md, CHANGELOG.md, DEVELOPMENT.md; тест NVDA (`just smoke`) для MP3 і повідомлення про відсутній кодер.
10. `just check`, `just build`, розмір exe, перевірка файлів із зібраного exe.
